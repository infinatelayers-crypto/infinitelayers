# Supabase-backed store control room and secure booking flow

The change adds a private Supabase admin area, six-image catalog management, fulfilment analytics, and anonymous booking through a database-repriced RPC. No blocker was found in the Next.js 16 session flow, admin allowlist/RLS enforcement, or PostgreSQL function and permission structure. The RPC rebuilds line items and totals from current product rows instead of trusting browser cart fields. A **confirmed blocker** remains in storefront fallback: backend errors become live-looking demo inventory, and the current build has permanently pre-rendered those non-orderable products.

Watch for: **confirmed blocker** — build-time Supabase failures publish static demo inventory whose IDs checkout rejects; **confirmed medium** — anonymous bookings have neither idempotency nor an abuse boundary; **confirmed medium** — image cleanup can leave unreachable public objects.

**Verdict**: NEEDS_CHANGES

## High-level view

Supabase SSR follows the Next.js 16 request model: Proxy refreshes cookies and forwards Supabase's no-cache headers, while the data layer and every mutation separately verify `getUser()`, allowlist membership, and database RLS. The SQL definer functions lock `search_path`, avoid RLS recursion, and keep order PII unavailable to anonymous table reads.

Catalog fallback has a **confirmed blocker**. Any configured Supabase query failure becomes `demoProducts`; `generateStaticParams` then made all six fallback products non-revalidating static routes in the current missing-table build, even though their IDs cannot pass the order RPC's UUID contract.

Checkout's trust boundary is sound, but three **confirmed medium** defects surround it: the UI ignores the canonical total returned by the server, ambiguous retries create duplicate orders, and direct anonymous RPC execution has no throttling or bot control. Product storage writes are admin-only, but **confirmed medium** best-effort cleanup can orphan files after partial upload, failed edit cleanup, or post-delete storage failure.

Admin status changes remain authorized, but **confirmed medium** fixed row limits make the “all” bookings view and dashboard totals incomplete at scale. Seven-day grouping has a **likely medium** India-store mismatch because it uses UTC rather than an explicit `Asia/Kolkata` day boundary.

### Supabase failures become immutable demo inventory

`fetchFromSupabase()` returns `null` for both missing configuration and configured query failures, and `getProducts()` converts either case to `demoProducts`; product detail lookup repeats the behavior (`src/lib/products.ts:44-81`). This is a **confirmed blocker** because a missing migration or outage fails open as orderable-looking inventory rather than an unavailable store or explicit preview mode.

`generateStaticParams()` consumes that fallback (`src/app/product/[slug]/page.tsx:10-14`). With the remote table absent, `.next/prerender-manifest.json:145-309` confirms six demo routes were emitted with `initialRevalidateSeconds: false`; `/` is likewise static (`.next/prerender-manifest.json:4-28`). Catalog actions invalidate only `/`, `/shop`, and a mutated real slug (`src/app/admin/actions.ts:55-62,200-202,242-243`), so creating the first real product does not evict those generated demo pages.

Demo IDs are `"1"` through `"6"` (`src/lib/demo-products.ts:4-75`), while the RPC rejects non-UUID IDs (`supabase/schema.sql:229-239`). Gate fallback behind an explicit development mode, fail closed for configured-backend errors, exclude fallback data from static parameters, apply the migration before building, and do not deploy the current generated artifact.

### Session refresh, allowlist checks, and RLS remain independent

```text
/admin request -> Proxy getClaims() + refreshed response cookies
               -> DAL getUser() + own admin_users membership row
               -> Server Action requireAdmin()
               -> table/storage policy public.is_admin()
```

`src/proxy.ts:5-35` uses the Next.js 16 `proxy` convention and covers Server Action POSTs made from admin routes. `getAdminIdentity()` validates the token with `auth.getUser()` and queries the caller's allowlist row (`src/lib/admin/auth.ts:13-38`); admin reads and every mutation repeat that check close to the data (`src/lib/admin/data.ts:96-102`, `src/app/admin/actions.ts:103-108,206-209,248-253`). Login signs out a valid but unapproved account before redirecting (`src/app/admin/actions.ts:64-93`).

`public.is_admin()` and `public.create_store_order()` are `SECURITY DEFINER` functions with empty search paths and schema-qualified application relations (`supabase/schema.sql:117-130,184-280`, mirrored in the deployment migration). The definer-owned membership lookup bypasses `admin_users` RLS without recursively invoking its own policy, while `auth.uid()` still reflects the caller. Products are public-read/admin-write; anonymous order-table privileges are revoked; authenticated order reads/updates remain admin-policy constrained; and public product-image reads pair with allowlisted writes (`supabase/schema.sql:282-326`).

### Canonical repricing is not acknowledged by the buyer

The route strips the browser cart to unique product IDs and bounded quantities (`src/app/api/checkout/route.ts:4-38,90-95`). The RPC then validates each product, checks availability, recalculates `price_paise * quantity`, caps the total, and stores canonical snapshots (`supabase/schema.sql:211-271`).

The route returns the authoritative total, but the client response type omits it and immediately clears the cart and navigates to success (`src/app/api/checkout/route.ts:123-132`, `src/components/checkout-form.tsx:57-69`). This is a **confirmed medium** pricing-consent defect: a changed price can become the booked total while the buyer saw only the stale local subtotal. Return canonical lines and require confirmation on a mismatch, or at minimum display the booked total without weakening server repricing.

### Public booking retries can duplicate or flood orders

No attempt key or unique idempotency constraint exists across checkout, the RPC, and `orders`. This is a **confirmed medium** duplicate-booking defect: if insertion commits but the response is lost, retrying the retained cart creates another order. Add an opaque attempt ID with database uniqueness and return the original result on replay.

`create_store_order` is executable directly by `anon` (`supabase/schema.sql:278-280`). Its validation protects row integrity, but this is a **confirmed medium** operational-abuse gap because a caller with the public project URL/key can bypass Next.js and create unlimited plausible bookings. Put creation behind a rate-limited, bot-resistant boundary that direct PostgREST calls cannot bypass, while retaining database validation.

### Public image objects have no durable cleanup path

Objects upload before `saveProductAction()` (`src/components/admin/product-form.tsx:143-193`). Browser closure, network loss, partial multi-file upload, or ignored edit cleanup errors can leave objects without a product reference (`src/components/admin/product-form.tsx:130-134,194-211`). Delete removes the row first and only logs subsequent storage failure (`src/app/admin/actions.ts:211-243`). This is a **confirmed medium** lifecycle defect with no UI retry handle; retain failed paths in a durable cleanup queue, reconciliation job, or soft-delete/outbox workflow.

### Booking views and metrics silently discard older rows

`getAdminOrders()` defaults to 250 rows, after which the page filters statuses and labels the result “All” (`src/lib/admin/data.ts:125-139`, `src/app/admin/(protected)/orders/page.tsx:24-66`). The dashboard derives every count and monetary total from a separate 500-row window (`src/lib/admin/data.ts:143-200`). This is a **confirmed medium** reporting defect: older open orders disappear and lifetime metrics become partial. Paginate listing data and compute counts/amounts with independent database aggregates.

Seven-day grouping uses UTC date keys (`src/lib/admin/data.ts:139-173`). For an India-facing store, this is a **likely medium** day-boundary defect: 00:00–05:29 IST bookings fall under the prior date. Define a business timezone and aggregate consistently in `Asia/Kolkata`.

### Runtime validation boundary

No test/spec files exist, and the remote project has no `products` table. The supplied lint, TypeScript, and build checks therefore do not execute migration syntax, grants, RLS roles, storage policies, token refresh, or RPC retry behavior; this pass could verify those contracts only statically.
